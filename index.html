// 02 — Research

研究互動 Demo果汁龍的研究實驗室

在資料庫系統實驗室研究資料探勘。每個 Demo 都用同一份超商交易一步一步演給你看，Java / Python 程式碼逐行對照，也可以下載回去跑。

研究地圖演算法「改良自誰」的關係圖、建議閱讀順序、比較表 效能比賽場產生上萬筆交易，實際跑 Apriori、FP-Growth、EFIM… 比快慢
  • Apriori 頻繁樣式探勘合併、剪枝、計數，每一步都對照程式碼
  • FP-Growth 頻繁樣式探勘交易壓進 FP-tree，再遞迴挖出樣式
  • Eclat：垂直格式與交集交易編號取交集，整個過程只掃一次資料庫
  • 封閉與最大樣式：CHARM樣式多到看不完？只留不重複的那些
  • 週期性頻繁樣式（PFP-tree）不只看出現幾次，還看隔多久出現一次
  • gSpan 圖形樣式探勘把分子畫成圖，找出常見的子圖
  • 關聯規則：信賴度與提升度買了 X 的人，真的也比較會買 Y 嗎？
  • 序列樣式：PrefixSpan先買什麼、下次再買什麼
  • GSP 與 SPADE 序列樣式序列樣式的另外兩種做法，三種一起比
  • Two-Phase 高效益樣式先用 TWU 上界篩候選，再算真正的效益
  • UP-Growth：用樹找高效益樣式四招收緊上界，候選比 Two-Phase 少
  • HUI-Miner 高效益樣式探勘出現最多的組合，不一定最賺錢
  • EFIM：投影與合併投影資料庫越縮越小，相同交易合成一筆
  • Top-k 高效益樣式不知道門檻設多少？直接要前 k 名
  • USpan 高效益序列樣式有先後順序，又要最賺錢
  • 📄 FOTH：不用 join 的高效益樣式讀論文做的：IndexSet 自己拆出子集合（Inf. Sci. 2024）
  • 增量探勘：FUP新交易進來，不用全部重算
  • CanTree：不用重建的 FP-tree固定順序插入，新交易只加一條路徑
  • IHUP 增量高效益樣式高效益樣式也能邊加資料邊挖
  • 滑動視窗頻繁樣式只看最近 W 筆，每進一筆即時更新
  • 串流近似計數：Lossy Counting・Space-Saving記憶體不夠時，怎麼知道誰賣最多
  • Count-Min Sketch用一格格計數器估次數，只會多算不會少算
  • Bloom Filter 與誤判率這張發票登錄過了沒？
  • HyperLogLog 基數估計今天來了幾位「不同的」會員？
  • 📄 HUOPS：滑動視窗高效益佔有率讀論文做的：佔整筆消費比例高的組合（Inf. Sci. 2025）
  • 📄 SWUPA：滑動視窗不確定樣式讀論文做的：商品只有存在機率時怎麼挖（ESWA 2026）
  • 空間資料：四元樹與共位樣式哪幾種店總是開在彼此附近
  • R-tree 與 kNN 查詢找最近的 k 家店，太遠的框不用打開
  • IR-tree 空間關鍵字查詢最近、又有賣咖啡和牛奶的店在哪
  • DBSCAN 密度分群不用先指定群數，月牙形也分得開
  • Skyline 查詢：BNL 與 SFS又便宜又近的店有哪些

每個 Demo 都附可直接執行的 Java 與 Python 程式碼，跟網頁上逐行高亮的是同一份。

// 03 — About

關於我關於果汁龍

Hi！我是果汁龍，目前是資料庫系統實驗室的碩一生。研究方向是資料探勘：從大量交易、時間序列與空間資料中，找出頻繁出現、高效益或具有週期性的樣式。

真實世界的資料庫一直在變，資料會新增、刪除，利潤也會浮動。我關心的是怎麼設計樹、清單或位元模式這類資料結構，加上剪枝策略，讓資料更新時不必整個重新掃描，也能有效率地維護探勘結果；另外也會接觸空間資料庫的索引與關鍵字查詢。

課堂與研究之外，我很喜歡自己動手做些小工具和小遊戲：記錄家裡電費的網頁、每天換一題的拼圖求解器、可以跟朋友連線對戰的卡牌遊戲……把遇到的小麻煩或好玩的點子做成真的能用的東西，是我最享受的事。
