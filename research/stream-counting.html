串流近似計數Lossy Counting 與 Space-Saving：記憶體不夠記全部，數出來的次數還是有保證

收銀機一直刷，商品一筆一筆進來，想知道「哪些商品賣得特別多」。最直接的做法是每種商品一個計數器，但真實的店有上萬種商品、資料又停不下來，記憶體不可能每種都記。 滑動視窗那頁是只看最近 W 筆、每個組合都精確計數；這頁反過來：從頭到現在的全部資料都算，但記憶體有限，只能近似，而且誤差有數學保證。 分頁一的 Lossy Counting 定期把次數太少的商品忘掉，次數只會少算、最多少 εN；分頁二的 Space-Saving 只有 k 個計數器，滿了就把最小的那個讓出來，次數只會多算、最多多 N/k。 例子沿用超商的六樣商品，再加上偶爾才有人買的果汁、布丁、泡麵、巧克力，讓記憶體不夠用。

為什麼少算不會超過 εN？

                    
把串流每 w = ⌈1/ε⌉ 筆切成一桶。看到第 N 筆時是第 b = ⌈N/w⌉ 桶，前面已經結束的 b − 1 桶共 (b − 1)·w 筆，不超過 N，所以 b − 1 ≤ N/w ≤ εN。整個保證就靠這件事：
                        一個商品在第 j 桶結束被刪掉時 f + Δ ≤ j，也就是「到那時為止它最多出現 j 次」，漏掉的量不會超過 j ≤ b − 1。

                    
它之後在第 b 桶又出現時，演算法不知道之前漏了多少，就保守地記 Δ = b − 1（之前最晚在第 b − 1 桶結束時被刪，那時最多 b − 1 次）。
                        所以表裡的每一列都滿足 f ≤ 真實次數 ≤ f + Δ，而 Δ ≤ b − 1 ≤ εN；不在表裡的商品，真實次數也不超過 εN。

                    
查詢時把門檻放寬成 f ≥ (s − ε)N：真實次數 ≥ sN 的商品，f 至少有 sN − εN，一定會被回報，不會漏；代價是可能多報幾個真實次數在 (s − ε)N 到 sN 之間的商品。
                        記憶體方面，論文證明表的大小最多約 (1/ε)·log(εN)，跟商品有幾萬種無關。

                

                

                    
跟滑動視窗比，以及跟實驗室研究的關係

                    
    
                        
  • 看的範圍不同：滑動視窗只看最近 W 筆，舊資料會「離開」，但視窗裡的次數是精確的；Lossy Counting 看從頭到現在的全部（叫做 landmark 模型），沒有資料離開，換成次數不精確。
    • 
                        
  • ε 是在拿記憶體換準確度：ε 越小，桶越寬、清得越少，越準但記得越多。試著把 ε 調大，看表變小、誤報變多。
    • 
                        
  • 只會少算、不會多算：f 是「確定看到的次數」，所以 f 本身已經 ≥ sN 的商品一定是真的頻繁；放寬門檻才會出現誤報。
    • 
                        
  • 從單一商品到商品組合：原始論文（Manku 與 Motwani，2002）也把同一招用在頻繁樣式上：一批一批讀交易，組合的計數一樣帶著 Δ、一樣分桶清理。
                            實驗室做的串流頻繁樣式、高效益樣式探勘，核心也是同一個問題：記不下全部時，要丟掉哪些、丟了之後誤差怎麼保證。

為什麼多算不會超過 N/k？

                    
每來一筆，剛好有一格的次數 +1（不管是原本就在記、放進空格、還是搶別人的格子），所以 k 格的次數加起來永遠等於 N。
                        k 個數加起來是 N，最小的那個一定 ≤ N/k。

                    
新商品搶走最小那格時，次數從 c + 1 開始，其中最多 c 次其實是被踢掉的商品的，所以記誤差 = c，而 c 是當時的最小值、≤ N/k。
                        之後這格只會因為自己出現才 +1，所以一直滿足 次數 − 誤差 ≤ 真實次數 ≤ 次數。

                    
反過來，沒在記的商品，真實次數不會超過它被踢掉時的次數，那時它是最小的；而接手那格的次數已經比它多 1、之後只會變大。
                        算一下就知道沒在記的商品，真實次數一定小於 N/k。所以只要 k ≥ 1/s，真實次數 ≥ sN 的商品一定還在格子裡，查詢「次數 ≥ sN」不會漏；「次數 − 誤差 ≥ sN」的更是保證真的頻繁。

                

                

                    
兩種方法怎麼選

                    
    
                        
  • 記憶體：Space-Saving 固定 k 格，事先就知道要多少；Lossy Counting 的表會隨資料長大縮小，只有上界。
    • 
                        
  • 誤差方向：Lossy Counting 只會少算（f ≤ 真實），Space-Saving 只會多算（次數 ≥ 真實）。兩個都附帶「最多差多少」，所以都能回答「哪些商品一定夠頻繁、哪些可能是誤報」。
    • 
                        
  • 熱門商品排行（top-k）：Space-Saving 的格子本身就是一份「目前最熱門的 k 個」，特別適合即時排行榜；資料越偏（少數商品賣超多），它越準。
    • 
                        
  • 速度：這頁的程式每次都把 k 格掃一遍找最小，好讀但慢；原論文用一種叫 Stream-Summary 的結構（同次數的放同一串、串依次數排好），每筆都是 O(1)。
    • 
                        
  • 還有別的路：Count-Min Sketch 用幾個雜湊表只記數字、不記商品名稱，也是只會多算。這些「用很小的摘要回答近似問題」的技巧，就是串流探勘研究的基本工具。
